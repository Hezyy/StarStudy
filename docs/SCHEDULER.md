# 星研规则排期与安全版本

实现位置：`src/scheduler/engine.ts`为无数据库写入的规则函数；`services/plans.ts`负责一致性校验、确认和事务；UI在`features/planner/`。规则引擎不依赖付费AI。

## 排期

输入当前日、初试日、任务与计时、预算、科目优先级、知识点状态和依赖、截止日及科目每日上限。当前页面处理全部未完成任务；已完成、跳过和已归档任务不自动改写。

优先级数字小者优先，数学默认1。按可用预算和科目权重分配，再允许未设硬上限的科目使用空余。用户指定科目每日上限是硬约束，总预算始终优先。学校考试、寒暑假、特殊日期和周复盘下周预算可在预览中一起调整，确认前不生效。

剩余时间为预计总量减去已记录实际时间，向上取整到分钟。单段可拆成1–240分钟。跨日保留原任务ID作为第一段，新段有稳定UUID与parentTaskId；重复内容以原日期区分，防止重复生成。原sourceKey仍保留在第一段，防止原Excel重复导入。

知识点前置依赖和显式任务依赖要求前置内容在更早日期安排完成；循环依赖拒绝。薄弱/未掌握知识点可增加基础复习，每知识点每周去重。没有明确关联的章节文本不会被猜测成可靠依赖，Excel导入后应逐步关联知识点。

已完成任务的计划字段受保护。运行/暂停中的计时必须先结束，才能应用调整。固定任务和已发生的实际学习会占用对应日期容量。任务超出预算、超过截止日、依赖缺失或科目停用时，明确保留为未排期内容，不标记完成、不静默丢弃。

预览展示新旧日期、预计时长、当日分配、原因、新增、延期、拆分、取消、受影响任务和无法安排的余量。差异每页100项，全部页均可查看。用户可确认、取消或回到表单修改。

## 应用与冲突

预览记录数据库状态令牌。确认时重新读取所有核心表、校验状态未变、检查ID/重复/预算/依赖，再在同一事务中写任务、必要预算及版本。发生异常整批回滚。预览后开始计时、修改任务或设置等会要求重新生成。

`PlanRevision`包含版本、时间、原因、前后快照、具体变化、approvedAt、kind；预算调整还有前后preferences。手动CRUD、改期、拆分和Excel导入也保留审计。

## 版本比较、撤销和历史恢复

比较按最新状态逆向重建选定版本的计划，而非只比较两个增量片段。撤销恢复目标调整之前的计划；历史恢复恢复到选中版本之后的计划状态。

只恢复计划字段，保留当前任务状态、笔记、completedAt和全部StudySession/MistakeReview。新增任务后来产生计时或已完成时不能被取消；旧预计量小于实际时长、计划字段又被修改、或会破坏后续显式依赖时列为冲突。用户可以保留冲突项，仅应用其他安全差异。没有安全差异时不允许伪装撤销成功。撤销本身新增审计版本，不删除旧版本。

手动创建任务或修改日期允许超预算并展示警告；自动规则和外部方案应用则严格检查预算。手动跨任务关系发生变化后，建议重新使用规则引擎检查所有依赖。

## 原件容量例子

用户原件54890分钟，默认平日90/周末120，2026-11-01至暂定初试2027-12-25可用41400分钟，缺口13490分钟。该计算在隔离测试库验证总工作量守恒及每日不超预算，没有擅自应用到用户数据库。配置真实假期、调整估时或减少不适用内容后应重新预览。
