# Linux部署、备份与恢复

本说明对应星研0.4.x。当前开发机没有Docker和真实Linux，尚未宣称本说明已完成空机端到端验收。先用独立测试服务器验证，确认数据、权限、备份恢复后再邀请真实用户。

## 准备

- Ubuntu22.04/24.04或Debian12/13，x86_64；至少2GB内存、5GB可用磁盘，构建建议4GB以上。
- 通过[Docker官方安装说明](https://docs.docker.com/engine/install/)安装Docker Engine与Compose v2。
- 安装Git、curl、openssl、iproute2；在本人控制的目录取得并审查源码。
- 正式域名A/AAAA解析到服务器，允许80/443入站。不要暴露5432数据库端口。
- ARM64未完成验收，安装脚本会拒绝；不要把镜像“能够拉取”当作兼容性验证。

从可信源码目录运行脚本，不建议把未知网络脚本直接管道执行。

```sh
bash scripts/install.sh
```

向导先检查系统、架构、内存、磁盘、Docker、端口与DNS。输入域名后核对解析结果，默认选择邀请注册；只有本人明确输入public才启用公开注册。生成随机数据库密码、会话秘密和一次性初始化口令，写入权限600的`.env`。不会覆盖已有.env。

首次启动按「数据库健康 → 迁移成功 → 应用健康 → Caddy」顺序执行。健康依赖配置使用[Docker Compose的ready/completed条件](https://docs.docker.com/compose/how-tos/startup-order/)。最后检查访问地址的HTTPS和健康接口；失败保留数据并给出诊断入口，不关闭证书校验。

打开提示地址，用初始化口令创建管理员；没有公开默认密码。创建后口令不能再次初始化，保持.env私密。

构建自动生成`/source/star-study-source.zip`，登录页和应用页脚已有「对应源码 · AGPL-3.0」下载入口，不依赖尚不存在的远程仓库。源码包按白名单包含该次构建的源码、迁移、锁文件和部署说明，不含Git历史、密钥、私人Excel、数据库或备份。部署修改版时重新构建，使包与实际运行代码一致；可以另加真实仓库链接，但不能用不匹配的上游版本代替本部署对应源码。

## 没有域名

安装时留空域名，会使用`http://127.0.0.1:8080`且只绑定回环地址；账号服务需要显式本地测试开关。可以在服务器本人会话访问，或通过受保护的SSH端口转发访问，不应把HTTP入口改绑公网。

回环测试不代表已验证Safari/Android PWA；正式安装和安全Cookie需要HTTPS。手机上的localhost指手机自身，不能直接访问电脑localhost。

## 服务与数据

- `database`：PostgreSQL17，命名卷`postgres_data`，无宿主公网端口。
- `migrate`：一次性迁移容器，成功后应用启动。
- `app`：Node24、非root、只读根文件系统、限制能力，服务仅在Compose内部暴露3000。
- `caddy`：对外80/443、自动HTTPS，证书/配置使用持久卷。
- 错题图片当前编码保存在PostgreSQL学习记录，不依赖Web公开上传目录。

容器重启不会清理数据库卷。不要使用`docker compose down --volumes`日常停止服务。

## 备份

```sh
bash scripts/backup.sh
```

默认保存至`backups/server/UTC时间-进程号/`，可用`STAR_BACKUP_DIR`指定仓库外的非Web目录。仓库内只允许已被忽略的backups目录，防止把自定义备份路径误提交。每份包含：

- `database.dump`：一致性PostgreSQL自定义格式转储，包含账户、图片、学习数据和迁移信息。
- `.env`、`compose.yaml`、`Caddyfile`：必要配置。
- `manifest.json`、`source-revision.txt`：备份格式、时间、应用版本和源码版本。
- 可选旧版`uploads/`目录；当前图片仍以数据库内容为准。
- `SHA256SUMS`：上述全部文件校验值。

脚本检查转储目录，拒绝Web目录，用严格权限创建备份并验证转储可列出。校验和不等于成功恢复：定期在独立空库恢复，并对任务、图片和计时进行抽查。备份含密码哈希、API密钥和用户数据；不要发送到公开Issue/GitHub，不要放在public/out或对外文件服务器。建议使用操作系统加密或专门备份工具加密，再异机保存，按本人需求制定保留策略。

可以由本人配置系统定时任务，例如每日02:30：

```cron
30 2 * * * cd /srv/star-study && /usr/bin/bash scripts/backup.sh >> /var/log/star-study-backup.log 2>&1
```

此行仅为教程，项目未替任何服务器安装定时任务。日志本身也需权限限制、轮转和告警；不要让自动任务把.env内容打印出来。成功备份会更新.env中的LAST_BACKUP_AT，下次重建应用后后台可显示这份部署元数据，尚不是实时备份监控。

## 恢复

先核对备份来源和版本，准备相同或已验证兼容的源码。切勿把未审查的陌生数据库转储当普通文档导入。

```sh
bash scripts/restore.sh /绝对路径/备份目录
```

脚本要求必要文件完整列入校验清单，拒绝遗漏、重复、未校验附加文件、符号链接和越界路径，并验证转储，要求输入RESTORE及YES。确认后先停应用/代理阻止新写入，再创建当前状态的最终安全备份，然后用PostgreSQL单事务恢复；避免备份期间产生的记录漏出恢复前快照。

恢复失败时数据库事务回滚，应用保持停止以便排查；不会静默删除卷。数据库恢复成功但健康检查失败时，也需诊断版本兼容与迁移情况。配置不会自动覆盖当前.env：异机恢复时自行核对域名、证书、会话秘密和Provider配置，不要误用原域名或旧密码。

真实用户账号删除后的旧备份可能仍含该账号数据；管理员应根据自己的隐私和保留规则管理备份。不能把删除在线账号当作自动擦除所有离线副本和历史备份。

## 更新

维护者实际发布稳定标签后使用：

```sh
bash scripts/update.sh vX.Y.Z
```

脚本要求当前目录为Git工作区且已有本人确认的可信origin，拒绝未提交源码改动。先创建在线安全备份，再拉取明确稳定标签；停应用/代理后再保存最后一份无新写入的更新前快照，然后检出、构建、迁移、重启与健康检查。迁移期间旧版应用不能继续写库。不会选择不明确的“最新版”，不会在失败时清理数据。

直接下载对应源码ZIP也可安装；源码包没有Git历史或远程地址，因此自动更新会明确拒绝猜测来源。需要自动更新时，由本人按发布教程接入可信仓库；不要在脚本中填写尚未创建的仓库地址。

失败时记录旧源码提交，维护阶段出错会保留停止状态，避免自动启动不兼容的应用。先运行诊断并检查迁移是否已提交；需要回退时，检出已知旧版本并从最后一份更新前快照恢复与它兼容的数据库。数据库迁移不是总能逆向执行，不能只启动旧镜像就假设回滚完成。保留.env、备份与源码版本直到验收通过。

## 诊断与卸载

```sh
bash scripts/doctor.sh
bash scripts/uninstall.sh
```

诊断输出Docker/服务状态、磁盘、数据库就绪、应用和HTTPS健康、备份清单，并仅统计最近日志异常类别，不导出可能包含秘密的日志原文。不要把原始docker inspect或完整环境变量粘贴到公开渠道。

默认卸载只停止服务并移除容器/网络，保留卷、源码、备份和配置。重新`docker compose up -d`可恢复。只有`bash scripts/uninstall.sh --purge`在两次明确确认并先备份后删除本部署数据卷，备份和配置仍保留。本次开发未执行任何真实服务器清理。

## 空白服务器验收清单

以下需要在实际Docker/Linux环境执行，目前不能用静态检查代替：

1. 在测试域名安装，HTTPS证书正常，公网5432不可访问。
2. 初始化管理员，错误口令和第二次初始化被拒绝；邀请默认、邀请码一次性有效。
3. A/B两个用户建立不同任务、图片与计时，刷新/重新登录后存在；A不能访问B或管理员接口。
4. 同账户第二设备读取记录，制造两端冲突，确认本机内容未被静默覆盖。
5. 重启所有容器，数据和图片仍在。
6. 创建备份，在另一个测试部署恢复，核对关联、图片、计时、复盘和历史。
7. 尝试损坏转储/校验值，恢复被拒绝且原数据不变；确认取消不写入。
8. 对两个实际稳定版本执行更新，模拟构建/健康失败，依说明恢复。
9. 默认卸载后重新启动，数据仍在；永久清除只在可丢弃测试环境验收。
10. DeepSeek配置后单独测试成功、无效密钥、超时与额度，检查日志不包含密钥/用户正文。

## 设备与离线手动验收

在PC Chrome、iPhone Safari、Android Chrome分别通过相同HTTPS地址测试：

1. 注册/登录及个人目标、新手引导，375/768/1440px下无横向溢出。
2. 安装到主屏幕，图标、名称、安全区域、键盘、底栏和抽屉可用。
3. 创建任务、计时开始/暂停/恢复/结束、完成撤销，刷新数字不重复累计。
4. 下载JSON/提示词、选择JSON和Excel文件、上传错题图片、重启后重新打开图片。
5. 联网等待缓存后，开启飞行模式冷启动、创建/修改任务并打卡，再联网核对数据。
6. 两设备同账号同步，刻意同时编辑并处理冲突；切换账号不混入任务。
7. B站具体视频保留选集参数，搜索链接明确标识，系统浏览器跳转可返回星研。
8. 开启减少动态效果，验证交互反馈仍可读；应用更新只在本人确认后刷新。

桌面WebKit模拟是回归工具，不能证明真实iOS文件权限、主屏幕生命周期和后台行为；当前未完成实机验收。
