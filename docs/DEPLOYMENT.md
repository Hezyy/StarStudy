# 星研统一安装与日常管理

在本人控制的 Linux 服务器，通过可交互的 SSH 终端运行：

```sh
curl -fsSL https://raw.githubusercontent.com/Hezyy/StarStudy/main/starstudy.sh | sudo bash
```

脚本来自公开仓库 [Hezyy/StarStudy](https://github.com/Hezyy/StarStudy)。这是以管理员权限执行远程代码的入口，可以先审查仓库脚本。安装后只需：

```sh
sudo starstudy
```

两个入口使用同一菜单，日常使用不需要记忆内部辅助脚本。

## 开始前准备

- Ubuntu 22.04/24.04 或 Debian 12/13，x86_64；至少 2GB 内存、5GB 可用磁盘，构建建议 4GB 以上。ARM64 与其他系统尚未验证，安装会停止。
- sudo/root 权限和交互式 SSH。最初命令需要系统已有 curl、sudo 和 Bash；极简系统缺少它们时先用系统包管理器或云控制台准备。
- 能访问系统软件源、Docker 官方源/镜像仓库、GitHub API/源码与证书服务。脚本自动准备缺少的依赖、Git、Docker Engine 和 Compose 插件，不自动移除已有容器运行时。
- 本人控制的域名，A/AAAA 指向本机公网地址。脚本只检查 DNS，不修改解析；不要保留指向其他机器的 AAAA 或 CDN 代理。
- 云安全组及防火墙允许入站 **TCP 80** 与实际选择的 HTTPS 端口。数据库没有对外映射 5432。

本机端口空闲不代表公网可达。HTTP-01 需要公网 80，HTTPS 使用高端口也不能绕过。当前未实现 DNS-01；80 无法开放时不会假装申请成功。参见 [Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)。脚本不会关闭防火墙、开放整段端口或修改 SSH。

## 菜单

| 选择 | 功能 |
| --- | --- |
| 1 | 安装；已有本部署则安全重试/恢复启动 |
| 2 | 更新到正式稳定版，或单独更新本机管理程序 |
| 3 | 普通卸载，或二次确认后永久清除本部署 |
| 4 | 版本、容器、数据库、域名、端口、证书期限和健康状态 |
| 5 | 最近日志或实时日志；Ctrl+C 退出实时查看 |
| 6 | 仅重启星研服务并检查健康 |
| 7 | 完整服务器备份 |
| 8 | 选择备份、校验、确认和恢复 |
| 9 | 系统、Docker、DNS、端口、证书、磁盘与配置诊断 |
| 0 | 退出 |

所有输入读取真实终端，不把下载的脚本当输入。无终端时提示使用 SSH。操作结束返回菜单，取消和中断不会自动清理数据。运维锁防止同一部署的更新、恢复和卸载交错执行。

## 首次安装

只需输入域名；邮箱和 HTTPS 端口可以回车。

- **域名必填**，例如 `study.example.com`，不带协议、端口或路径。
- **邮箱选填**。填写后用作 ACME 联系邮箱；留空不阻止申请和续期，但可能收不到通知，不需另注册证书服务账号。
- **HTTPS 端口选填**。默认安全随机选择 20000–60000 的空闲端口，最多 50 次；指定端口也检查合法性、系统监听和 Docker 已发布端口，80 留给 HTTP-01。

首次安装锁定真实稳定发行版；尚无稳定版时，额外输入 `INSTALL DEVELOPMENT SNAPSHOT` 才接受展示提交号的固定开发快照，不冒充生产稳定版。所选版本缺少本管理协议时停止，不运行不兼容脚本。

源码位于 `/opt/starstudy`，管理配置 `/etc/starstudy`，命令 `/usr/local/bin/starstudy`。自动生成数据库密码、会话密钥、一次性初始化口令、安装身份和至少 128bit 随机访问路径；私有配置权限受限。域名、端口、路径、密钥在重启、重试和更新后保留。

不明已有目录、同名命令、Docker 资源或本地改动会阻止相关操作，不会覆盖。旧版没有安装身份的目录需要人工核对，不能自动冒认。普通卸载后再选安装复用原配置与数据卷。

启动顺序为数据库健康、迁移成功、应用健康、Caddy。Caddy 容器内监听 80/443，宿主实际 HTTPS 端口映射到容器 443；HTTP 跳转保留高端口，TLS-ALPN-01 禁用，HTTP-01 与自动续期使用持久化 ACME 状态。

只有健康与可信 HTTPS 检查通过才输出成功、版本、完整地址和管理员初始化方式。**完整随机路径及初始化口令请私下保存，勿贴公开 Issue。** 默认邀请注册，没有通用管理员密码，随机路径不能替代账号认证。

前端构建、路由、资源、API、Cookie、Manifest、Service Worker 与离线缓存使用一致前缀；构建/运行不一致拒绝启动。修改域名、协议或端口会产生另一浏览器来源，修改路径会改变应用作用域，应先备份，不能只改代理就假设缓存自动迁移。

## 备份和恢复

菜单 **7** 默认保存至 `/var/backups/starstudy/<安装身份>/backup-<时间>-<后缀>/`，管理员专用权限。完整格式包含：

- PostgreSQL 自定义格式转储：账户、任务、计时、错题图片和迁移信息。
- 私有配置、Compose/Caddy 配置、安装身份、应用和源码版本。
- Caddy 数据/配置归档：证书、私钥、ACME 账号和续期状态。
- 可选旧上传目录、格式清单与全部文件 SHA-256。

转储可读、校验清单与归档安全检查通过后才成为正式备份。禁止放 Web 目录或未忽略的仓库目录。旧备份不含证书会提示，恢复保留当前证书卷。

备份包含凭据与用户数据，应加密并异机保存，不能提交 GitHub。本机备份不抵御整机损毁；未自动配置定时任务或异地存储。

菜单 **8** 列表选择后校验并预览；要求 `RESTORE` 和 `YES`。确认后先停写、备份当前状态，再用 PostgreSQL 单事务恢复。拒绝损坏、缺失/重复清单、链接、越界、未校验附加文件和空转储。

SQL 失败事务回滚，服务保持停止；**SQL 已提交后证书复制/健康失败不等于数据库回滚**，错误显示实际阶段，保留恢复前备份。当前域名、端口、路径和私有配置不被旧配置覆盖。异机恢复、不同域名或版本兼容应先在独立测试机核对，不能自动猜测。

## 更新

菜单 **2 → 1** 只选 GitHub 真实、非预发布的稳定版本。没有稳定版明确停止，不把 main 当稳定发行版。未提交源码、归属不明或版本不兼容也会停止。

先验证备份和目标版本，停写后另存最终快照，再构建、迁移、启动和检查。保留环境配置、身份、域名、端口、路径、数据库和证书卷。失败保留备份，不做删除卷的自动回滚；不能只切回旧镜像就假设数据库也回退了。

菜单 **2 → 2** 单独更新管理程序：解析官方固定提交，校验 Git blob、长度、标识与 Bash 语法，验证临时文件后原子替换。网络/校验失败保留旧命令。会话不热替换，退出后重新运行 `sudo starstudy`。

## 卸载

菜单 **3 → 1** 仅移除本部署容器及网络，保留数据库、证书、源码、配置与备份；之后菜单 **1** 复用配置启动。

菜单 **3 → 2** 先列出资源、验证安装身份与所有权、备份校验，要求 **`DELETE STARSTUDY DATA`** 和再次确认。仅删除明确属于本部署的资源；不明、外部或共享资源阻止删除。以实际清单为准，保留独立最终备份；不清理整个 /opt、Docker 或其他项目。失败会报告剩余项。

## 常见问题

| 提示 | 处理 |
| --- | --- |
| 需要真实终端 | 使用交互 SSH，不从无人值守任务执行菜单 |
| DNS 不匹配 | 核对 A/AAAA，移除旧记录/代理，等待生效后重试 |
| 无法确认公网地址 | 检查出站网络、代理、NAT；不要绕过验证 |
| 端口占用 | 核对已有服务；脚本不替你停止其他项目 |
| 证书/HTTPS 超时 | 检查公网 80、实际 HTTPS 端口、云安全组、防火墙和菜单 5 |
| GitHub/软件源不可达 | 修复网络重试，失败下载不替换旧命令 |
| 不明目录/资源 | 人工核对并保存数据，不伪造身份标记或删除卷来通过检查 |
| 没有稳定版 | 等待维护者完成验收并发布真实版本 |
| 迁移/恢复失败 | 核对阶段、菜单 9 与备份，不反复强行启动不兼容镜像 |

状态与日志隐藏随机路径、密钥和密码；仍不应公开原始环境文件、完整 docker inspect 或备份。脚本未实现 DNS 服务商授权或绕过网络限制。

## 验收与设备

本轮实际结果见 [管理脚本交付与测试](MANAGER_DELIVERY.md)。静态检查、mock、浏览器/PGlite、Linux/Docker CI 与公网证书是不同层次。正式邀请朋友前在独立服务器验证：

1. 公网可信证书、80、实际 HTTPS 端口、正确跳转。
2. 初始化、邀请注册、两用户隔离、登录/退出。
3. 随机前缀下页面、静态文件、API、源码下载与 PWA。
4. 任务/计时/错题图片在刷新、容器重启、完整备份恢复后逐项一致。
5. 两设备冲突确认、离线编辑后同步不丢数据。
6. 普通卸载后恢复；仅可丢弃环境测试永久删除，其他项目不受影响。
7. 有两个实际稳定版本后演练更新、迁移失败与恢复。

### 设备与离线手动验收

真实 iPhone Safari、Android Chrome 和桌面浏览器用同一 HTTPS 地址，安装主屏幕，检查 375/768/1440px、键盘、底栏、抽屉；上传/重开图片、选择 Excel、下载备份；联网缓存后飞行模式冷启动，创建任务、计时打卡，再联网核对。应用更新应先提示，不能刷新未保存编辑。桌面 WebKit 不能替代 iOS 文件权限、主屏幕和后台生命周期。

构建提供实际部署对应的 AGPL 源码包，不含 Git 历史、密钥、私人 Excel 或备份。修改版重新构建并向使用者提供对应源码。
