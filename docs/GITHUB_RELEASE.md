# GitHub 发布与隐私保护

公开仓库为 [Hezyy/StarStudy](https://github.com/Hezyy/StarStudy)，默认分支 `main`。本项目已经公开，不要重新建仓或改名。服务器用户直接按 [统一部署说明](DEPLOYMENT.md) 使用管理菜单。

## 维护者发布前检查

1. 检查 Git 状态、待提交文件和完整发布差异，保留用户尚未提交的修改。
2. 运行 lint、类型、单元、构建、安全扫描及受影响的浏览器/部署测试；以真实结果为准。
3. 私有环境文件、数据库、用户图片、原始 Excel、证书/私钥、备份、测试产物不得进入 Git 或源码包。`.env.example` 只放空值和合成示例。
4. 检查 Git 历史；如果密钥曾公开，先撤销/轮换，再制定历史处理方案，不用强推掩盖。
5. 保留 AGPL-3.0-only 许可证，并为实际运行的修改版提供对应源码。
6. 公开仓库可见不代表已经生产部署或获得可信 HTTPS 证书；正式标签必须与实际测试结论一致。

## 私有开发历史与公开发布分支

旧本地基线包含原用户个人默认配置，因此 `codex/open-platform` 的历史应继续保留在本机。不要直接把该分支、`master` 或所有分支推送公开仓库。

`npm run release:prepare` 从当前已提交、已扫描的源码生成 `codex/public-release`。首次公开提交不继承私有开发历史，后续只接续已有公开分支；历史验收截图从公开树排除。该工具不切换或清理工作区，也不自动推送。它要求干净的提交副本；有用户未提交修改时应保留原工作区，在隔离副本准备，不能偷偷暂存或覆盖。

正常发布前先读取远程 main，确认没有其他更新。只推送经过审查的公开分支到 main，拒绝强推，不覆盖远程代码。上传后重新查询提交和文件树，并实际读取 Raw 管理脚本，检查内容与提交的 Git blob 一致。不得仅凭上传命令返回就认定成功。

## 统一脚本与稳定版

根目录 `starstudy.sh` 的公开地址：

```text
https://raw.githubusercontent.com/Hezyy/StarStudy/main/starstudy.sh
```

管理脚本自更新解析固定提交、校验 blob/长度/Bash 语法并原子替换。应用更新仅接受真实稳定发行版，不无条件拉 main。尚无正式发行版时必须明确停止；首次安装固定开发快照需要额外确认。

发布稳定版本前，在独立 Linux/Docker 测试环境通过部署、备份恢复、更新与权限检查，再创建真实稳定发行版。不能为使更新菜单“看起来可用”随意打稳定标签。

## 登录与授权

使用本人已有 GitHub 登录、Git Credential Manager、SSH 或 GitHub CLI。不要在聊天、文件、远程 URL 或日志里粘贴密码和访问令牌。任何授权由本人在官方登录流程完成；本项目不要求为使用管理脚本安装 GitHub 插件。
